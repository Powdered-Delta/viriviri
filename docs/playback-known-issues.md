# 播放已知问题

## PLAYBACK-001：暂停时调节尺寸／曲率，视频画面逐帧前进

- 状态：**已知 bug，未解决；按用户 2026-10-23 的安排延后处理。**
- 后续处理阶段：快进／快退功能，与 seek、暂停帧保持、恢复播放和输出交接一起排查。
- 当前不继续试验修复，不作为本轮版本已解决项，也不自动安排定时跟进。

### 现象和复现入口

1. 在正式播放入口播放视频，然后暂停。
2. 使用现有控制调整视频尺寸／缩放或曲率。
3. 预期：几何变化，视频仍停在同一帧。
4. 用户实测：暂停时画面也会逐帧往前走。

这里已确认的是用户看到的画面前进；播放器 currentPosition 与帧时间戳是否同步变化，
尚无本轮测量结果，后续需要分别观察，不能将它们混为一个时钟。

### 当前保留的实现

视频几何变化时，继续按最终宽、高、半径创建视频面板并更换 SDK Surface；
保留 B、统一 Z 补偿和现有 33 ms 合并节奏。弹幕保留 UI 资源，字号38px、
描边4px，底部15%留给字幕。后续修复必须维持缩放同步及曲面可见。

### 已有线索与失败方案

- Media3 1.4.1 更换输出 Surface 会重置首帧状态，暂停时也可能输出下一帧。
  这能够解释现象，但尚未形成通过实机验收的修复。
- 保留旧视频 PanelSceneObject／Surface，改用视频 reshape 的候选已经失败：
  用户反馈缩放不同步、进入曲面直接消失；候选已撤回。
- 不能只凭参数、Surface 身份检查、构建或 JVM 测试恢复该候选。
- 高频重建显示对象仍有潜在资源开销；目前没有性能测量，不把复用 Surface
  等同于已消除网格、合成层和原生对象的重建成本。

完整证据、失败与回退 APK 哈希见
[视频 reshape 失败记录](video-reshape-failure-2026-10-23.md)。

### 与快进／快退一起解决时的检查项

- 分别核对播放器位置、实际显示帧时间戳和弹幕时钟。
- 暂停时调整几何保持同一帧；显式 seek 后显示目标位置的帧。
- 连续快进／快退采用最新目标，旧回调不能覆盖新目标或解绑新输出。
- seek 结束后维持原来的播放／暂停状态，恢复播放时音画及弹幕同步。
- 同时回归缩放同步、平面／曲面切换可见性及最终边界。
- 测量连续调节的创建耗时、帧间隔与资源释放，不只评估观感。
