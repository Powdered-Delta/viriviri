## 3. 术语与对象边界

- **舞台范围**：完整 16:9 布局区域，当前基准 1.6 × 0.9 米。它是尺寸基准，
  不要求存在一张单独可见的黑色矩形面。
- **视频范围**：按源比例或用户明确选定的显示比例，放入舞台范围后得到的物理矩形。
- **视频载体**：运行时子实体 `videoSurfaceEntity`，承载视频面板及其 SDK 开孔。
- **视频 layer**：compositor 绘制视频像素的对象，不由普通 mesh 绘制视频像素。
- **视频开孔**：SDK 为该面板生成、作用于主场景缓冲的几何与材质。下文用这个名称指视频对应的
  hole-punch，避免与环境遮罩、压暗层或弹幕自身的面板几何混称为“裁切器”。
- **压暗层**：工作台显示时的半透明覆盖内容；不是视频开孔，也不是视频输出目标。
- **环境**：场景模型／天空背景，进入主场景缓冲。当前没有一个可直接设置低 zIndex 的“环境 layer 组”。

逻辑关系如下；“共享布局”不表示所有子层具有相同宽度。

```text
工作台移动锚点
└─ 舞台根 spatialized_video_panel
   ├─ videoSurfaceEntity
   │  └─ 同一个 PanelSceneObject
   │     ├─ 视频 compositor layer
   │     └─ SDK 视频开孔 mesh / 材质
   ├─ 弹幕面板：完整舞台范围
   ├─ 压暗面板：完整舞台范围，独立可见性
   └─ 其他工作台面板：跟随移动，各自布局／输入，不自动跟随视频曲率

字幕：目标规格预留；当前 PlaybackStageLayer 只包含 VIDEO / BACKDROP / DANMAKU。
环境：独立场景内容，不属于上述视频载体。
```

## 4. 尺寸与纹理契约

设缩放值为 s，舞台宽高为 W = 1.6s、H = 0.9s，显示比例为 a。
AUTO 使用源宽 × 像素宽高比 ÷ 源高；用户明确选择比例时使用该比例。

```text
若 a ≥ W/H：视频宽 = W，视频高 = W/a
否则：     视频宽 = H*a，视频高 = H
```

| AUTO 源比例，s = 1 | 视频／视频开孔范围（米） | 弹幕／压暗范围（米） |
| --- | --- | --- |
| 16:9 | 1.6 × 0.9 | 1.6 × 0.9 |
| 4:3 | 1.2 × 0.9 | 1.6 × 0.9 |
| 9:16 | 0.50625 × 0.9 | 1.6 × 0.9 |

必须满足：

1. 视频与视频开孔使用相同的物理范围、圆柱参数和中央锚点。
2. 视频纹理使用 SDK `Crop.NONE`，完整帧 UV 为 [0,1]。固定的 1920×1080 像素配置
   **不是**内容已在 16:9 画布中填黑边的证据，不得再次按源比例裁切。
3. 缩放只计算一次。当前尺寸烘入 shape，原生 scale 与 footprint 保持单位值。
4. 弹幕的物理区域保持 16:9，UI 栅格保持匹配比例（当前 1280×720 dp），不对字体做非等比压缩。
5. 全舞台覆盖层可以比竖屏视频更宽；这不构成尺寸不同步。视频与**自己的开孔**错位才是故障。
6. 比例、缩放、曲率变化不能新建播放器、替换视频 Surface 或重新加载媒体。

## 5. 坐标与曲率契约

详细证据见 [坐标说明](spatial-coordinates.md)。应用侧使用 API 坐标，SDK 在原生边界进行 Z 反射。

| 空间 | 约定 |
| --- | --- |
| API 世界空间 | 初始朝向下 +X 右、+Y 上、+Z 前；世界轴不随转头旋转 |
| 舞台局部空间 | 初始 local −Z 朝观看者；移动／旋转后须合成父级姿态 |
| 原生渲染空间 | 对应位置 Z 反号；调用 Kotlin API 时不得自行再翻一次 |

### 5.1 用户已确认的整体缩放规则

定义 r0 为未缩放的曲率控制半径、z0 为未缩放的原始层间距、s 为整组缩放倍率。
曲率修正值为 −r0。用户确认的公式为 **(原始 Z + 曲率修正值) × 缩放倍率**。
对于已核验的轴原点圆柱，API 局部中央点在 +有效半径：

```text
W = W0 × s                 H = H0 × s
有效半径 rEffective = r0 × s
平面：carrierLocalZ = z0 × s
圆柱：carrierLocalZ = (z0 − r0) × s = z0 × s − rEffective
中央点：carrierLocalZ + rEffective = z0 × s
worldPose = stageWorldPose × carrierLocalPose
```

这保持整组几何相似：W/rEffective = W0/r0。只能缩放局部几何，不把工作台世界位置乘 s。
两种等价实现只能选一种：烘入全部有效尺寸／半径／局部 Z，或使用经 SDK 验证的统一变换。
不能只烘入宽高，也不能使用有效半径后再把整项重复乘 s，造成半径补偿乘 s²。

曲率控制范围仍为未缩放 r0 的 1.5 米至小于 8 米；达到该控制上限回到平面。
有效半径可以超过 8 米，例如 r0=7.9、s=2 时 rEffective=15.8，不能因此误转回平面。

### 5.2 修复前证据与本版实现

修复前直接运行编译出的 `PlaybackStageController`，得到以下历史结果：

| r0=2.7，视频 z0=0 | s=1 | s=1.5 | s=2 |
| --- | --- | --- | --- |
| 修复前舞台宽（米） | 1.6 | 2.4 | 3.2 |
| 修复前有效半径（米） | 2.7 | 2.7 | 2.7 |
| 应有有效半径（米） | 2.7 | 4.05 | 5.4 |
| 修复前视频载体 local Z（米） | −2.7 | −2.7 | −2.7 |
| 应有视频载体 local Z（米） | −2.7 | −4.05 | −5.4 |

曲率路径也已直接执行：在 s=2 时，r0 从 2.7 改为 1.5，修复前视频 local Z 从 −2.7 改为 −1.5，
并非一直没有修正；目标应为 −5.4 改为 −3.0。缺少的是半径和整个局部 Z 的共同倍率。

修复前遗漏发生在几何派生链，而非输入发出阶段。本版 `buildLayout()` 通过 scaledBy 派生有效半径，
布局将原始层间距乘 s，`PlaybackStageLayerGeometry.localPose()` 再减有效半径。
本版在 s=2、r0=2.7 时视频 Z 为 −5.4，r0 改为 1.5 后为 −3.0。
三层共用该布局，原生 scale 仍为 (1,1,1)，避免重复应用倍率。

这项缺口**不能单独证明视频开孔相对视频漂移的全部根因**：视频 z0=0 时，修复前代码的中央点
仍满足 −r0+r0=0。若同一个视频 SceneObject 中开孔与 layer 真正一致，二者会一起接受这项错误的
缩放语义。还需区分实际漂移的对象，并核对最终几何／原生变换，不能据此宣布已找到全部视觉根因。

原始未缩放层间距：视频 0、压暗 +0.01、弹幕默认 −0.01 米；弹幕调试按钮可改变自身间距。
补偿必须从未缩放 base 和 r0 绝对重算，再整体乘 s；不累加，不直接向世界 Z 加减局部半径。

**这里约束的是中央点不漂移，不是所有边缘点保持原位。**
圆柱宽度沿用弧长语义：弧角为 W/rEffective，弦宽为 2rEffective·sin(W/(2rEffective))。半径变化会改变边缘位置和
投影外观；不能据此单独判为漂移。若产品要求固定弦宽／固定视角，需要另外修改尺寸定义并审核。

还必须验证：SDK 最终生成的面板开孔，是否在上述生成器之外另有平移、归一化或 footprint 变换。
通用圆柱生成器的数学关系，不能替代对实际面板 mesh 的测量。

## 6. 层级、可见性与环境的关系

当前配置：视频 zIndex 1、压暗 2、弹幕及其他工作台 UI 3。视频为 OPAQUE；透明 UI 为 ALPHA_BLEND。
这是源码配置事实，不是实机已经符合第 2 节目标顺序的结论。

- zIndex 排序 compositor layers，不修正几何位置、半径或开孔边界。
- 相同 zIndex 的层还会按实体原点到头部的距离排序，不能把同为 3 当成工作台必定高于弹幕。
- 逻辑父子关系不创建一个统一离屏合成组。
- 当前 SDK 开孔改变主场景缓冲的透明区域，让对应视频 layer 可见；不修改环境模型本身。
  但开孔边界与视频不匹配，确实会在视觉上表现为环境被错误挖空或出现黑色区域，这是待修故障。
- 视频必须独立完整可见，不能依赖弹幕字形、字幕或工作台的透明区域才显示。
- 压暗层应由工作台可见性决定；初始 Visible(false) 不能被当成始终隐藏，运行时宿主会更新它。
- 视频开孔不拥有输入、独立可见开关或媒体 Surface；弹幕／压暗面板不拦截舞台射线。
- 后续若改变 layer 策略或开孔机制，必须先证明视频、透明 UI 与环境共同显示的完整路径。
  本稿不预先决定“删除 SDK 开孔”或“新建一张自定义裁切面”。

## 7. 当前更新流程与实现边界

```text
app state（比例、缩放、曲率）＋ Media3 视频尺寸
  → PlaybackStageController
  → PlaybackStageLayout（最新完整布局）
  → PlaybackStageGeometrySystem（等待全部现有面板就绪）
  → PlaybackStagePanelRenderer
      生成全部配置 → 调整舞台／抓取条间距 → 采样舞台世界姿态
      → 全部 reshape／完整帧 UV／单位 scale
      → 全部绝对局部姿态／原生世界姿态
```

控制器会合并连续输入，面板缺失时保留待应用请求，实例替换后重放最新布局；成功回调后记录已应用版本。
创建、reset 和调试参数应经过同一入口，不新增逐层监听器或定位旁路。

当前“成功”表示宿主调用完成，**不是 SDK／GPU／compositor 对实际显示结果的确认**。
同一同步函数提交三层，也不是原生合成器事务保证。移动舞台后的后续姿态传播依赖 SDK 的父子变换系统；
不能用一次提交日志证明后续帧仍重合。

## 8. 漂移排查必须取得的证据（审核后执行）

用户进一步描述：“裁切器”是一块弯曲黑色窗口，视频必须透过它才能正常显示；打开工作台时，
窗口外呈网格状半透明。此处记录的是外观事实，不直接把它等同于某一个 SDK 对象。

[组件与参数流向图](diagrams/playback-stage-components.html)把视频开孔标为 A、弹幕自身几何标为 B、
压暗面板标为 C，供对象辨认。SDK 0.13.2 的 `PanelShape` 构造过程已核实：先把生成的 mesh 装到
传入的 SceneObject，再把同一个 SceneObject 传给 SceneCylinderLayer。源码没有一个独立的 A 实体，
可单独漏调 local Z；但 B/C 是其他面板，各有自己的 mesh 与 layer。

| 待确认项 | 要取得的证据 | 不能作为结论的替代品 |
| --- | --- | --- |
| 实际漂移的是哪一个对象 | 区分视频开孔、弹幕面板几何、压暗面板与可见视频边界 | 仅凭黑色矩形外观命名为视频裁切器 |
| mesh 是否收到新尺寸／半径 | 实际生成的 mesh 顶点／边界及其对象身份，注明坐标空间 | 仅打印传入的 shape 参数 |
| 中央点是否真正固定 | 实际 mesh 中央点合成到世界后的结果，与视频层实际姿态对照 | 仅计算 base−r+r=base |
| 父子变换是否又被覆盖 | 提交后及后续 SDK 帧的 ECS／原生姿态、父链和 scale | 只打印 setPosition 的实参 |
| 两条渲染路径是否同时更新 | 同次变更的布局版本、mesh/layer 实例、实际参数与生效时序 | Kotlin 函数顺利返回 |
| 可见性是否造成假象 | 平面／曲面下，工作台开关及弹幕有无的对照 | 把所有遮挡问题归于 zIndex |

必须先取得这些证据，再选择修复位置；不能先换补偿符号、另加偏移量或额外 mesh 来贴合症状。

## 9. 验收矩阵与通过标准（待审核）

| 场景 | 必须观察到的结果 |
| --- | --- |
| AUTO：16:9、4:3、9:16 | 完整视频比例正确，视频边界与自己的开孔一致，竖屏两侧是环境 |
| 平面 → r=7.9 → r=2.7 → r=1.5 → 平面 | 中央锚点不跳移，开孔始终贴合视频；回平面无残留位移 |
| 缩放 0.7、1、2；交替改变半径 | 视频／开孔按同一尺寸更新，弹幕仍满舞台且字形不挤压 |
| 移动并旋转整组，再改变半径 | 补偿沿舞台局部轴生效，不出现固定世界 Z 方向的漂移 |
| cozy／透视；工作台开／关 | 无额外黑色视口，无环境穿出视频或被错位挖空 |
| 无弹幕／有弹幕 | 完整视频可见性一致，不靠字形开孔显示视频 |
| 冷启动恢复已保存参数；快速连续调节 | 不遗留旧半径、旧尺寸或仅部分层更新的状态 |

建议数值门槛：稳定后的中央锚点误差 ≤1 mm、视频与开孔边界误差 ≤2 mm；这是待审核的验收目标，
不是现有测量结果。判定边界时需使用同一曲面坐标定义，并考虑已说明的弧长／弦长差异。
动态过程中不得出现持续分离；若存在瞬态更新差异，须记录持续帧数供审核，不以静态通过掩盖。

必须同时满足数学／调度测试、实际 mesh/layer 对照与头显视觉验收。构建通过不能替代后两项。
纹理比例已通过的结果必须持续保留，不能为修复开孔漂移重新引入推算黑边、二次裁切或字形拉伸。
